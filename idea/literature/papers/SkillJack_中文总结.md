# SkillJack：Persistent Skill Backdoors in Self-Evolving Agents

## 文献信息

- 作者：Zonghao Ying, Xiangfan Wu, Huiyu Wu, Xing Zheng, Huangsheng Cheng, Xiaorong Shi, Jing Guo
- 机构：Tencent Zhuque Lab
- 版本：arXiv:2608.03509v1，2026-08-04
- 论文：https://arxiv.org/abs/2608.03509
- 代码：https://github.com/Tencent/AI-Infra-Guard/tree/main/research/skilljack

## 一句话总结

这篇工作发现：自进化 Agent 会把历史轨迹提炼成长期保存的 skill，因此攻击者只要污染“经验层”，就可能借助 Agent 自己的 skill 提炼流程，把一次性的恶意经验“洗白”成表面正常、会被未来任务自动调用、且删除原始经验后仍然存在的持久后门。

## 论文解决了什么问题

过去的 Agent memory poisoning 通常依赖一个条件：未来任务必须再次检索到被污染的记忆，攻击才会生效。SkillJack 关注的是更深一层的风险——如果系统会把经验自动压缩、抽象并固化成 skill，那么恶意影响可能从临时记忆跨层升级为独立的行为资产。

论文将 experience-to-skill 流程抽象为四步：加载经验、转换/提炼、持久化、面向新查询进行路由。攻击者只能向经验库加入污染轨迹，不能直接修改 skill 库、提炼代码或路由器。攻击成功要求提炼出的 skill 同时满足：没有被安全检测器识别、会被路由到后续任务、并能诱导不符合策略的行为。

## SkillJack 的核心设计

作者设计了“抗转换载荷”（transformation-resilient payload）：不使用明显的恶意措辞，而是把危险动作包装在看似合理的功能叙事中，例如备份、归档、统一管理、错误恢复等。因为 skill 提炼器的目标是保留可复用的操作流程，它可能在压缩和改写文本时保留真正的危险动作，却把上下文和元数据改写得更加中性。

论文用三个性质描述这一风险：

1. Sanitization whitewashing：提炼后的 skill 比原始污染轨迹更难被检测。
2. Cross-layer promotion：一次性的经验被升级为可反复调用的持久 skill。
3. Persistence isolation：skill 与源经验分开存储，删除源记录并不会自动删除其派生 skill。

## 实验设置

作者在两套 experience-to-skill 系统上测试：SkillX 和 Anything2Skill（A2S）。统一使用 DeepSeek-v4-flash 完成提炼、路由、判断和 Agent 推理。

数据集共 150 条 AppWorld 格式轨迹：

- 65 条经过功能化包装的污染轨迹；
- 65 条与之配对、措辞直接恶意的基线轨迹；
- 20 条干净轨迹。

风险类别包括数据外泄、权限提升、未授权转账和持久后门。SkillX 从两组污染轨迹中分别提取出 264 和 241 个 skill；A2S DOC 模式只从 27 条功能化污染轨迹中产生了可复用输出，后续组成 30 个 skill 的检索库。

检测采用正则模式匹配和同一个 LLM judge。论文中的“触发率/ASR”主要是“路由到可疑 skill，且通过策略违规代理指标”的比例，不等同于真实环境中的成功入侵率。

## 关键结果

### 1. Skill 提炼显著降低可检测性

在 SkillX 中，LLM judge 能识别 98.5% 的原始功能化污染轨迹，但只能识别 11.4% 的派生 skill；正则检测也从原始轨迹的 44.6% 降至 11.0%。直接使用恶意措辞的派生 skill 检出率为 27.0%，说明“合理功能包装”确实提高了隐蔽性。

A2S 也出现同方向现象：DOC 模式中，原始污染轨迹的 LLM 检出率为 100%，派生 skill 为 44.4%。这说明白化现象不只存在于 SkillX，但两个系统的提炼产率和 skill 表示方式差异很大。

### 2. 后门会脱离源经验继续存在

在 25 个配对任务中，skill 路径最初触发率为 40.0%；删除源污染轨迹后仍为 32.0%。也就是说，原本通过 skill 触发的案例中有 80.0% 在删除源记录后继续触发。仅清理 memory 无法撤销已经派生出来的 skill。

### 3. 派生 skill 会在后续任务被调用，也可能误触发

SkillX 在包含 305 个污染 skill 和 51 个干净 skill 的库上测试：32 个攻击导向任务的代理触发率为 56.2%，15 个干净任务也有 20.0% 触发。这既扩大了影响范围，也可能暴露异常。

A2S DOC 的 65 个攻击导向查询中有 89.2% 触发代理指标；20 个干净查询中有 95.0% 会检索到恶意 skill。后一个数字是“检索率”，不是已经执行危险行为的比例。由于 SkillX 使用原生 LLM 路由和混合 skill 库，而 A2S 使用词法检索及不同的 skill 库，两者的 56.2% 与 89.2% 不能作为系统安全性的直接排行榜。

### 4. 中性元数据会影响安全判断

在 SkillX 的 30 个采样 skill 上，只让 LLM judge 看代码时检出率为 36.7%；同时提供中性名称和文档后，完整 skill 的检出率降到 10.0%。这表明 judge 容易受“看起来合理”的名称和说明影响，不能只依赖 skill 的表面语义做静态审核。

### 5. 行为监控有帮助，但防御叠加并不一定单调变好

在 SkillX 的 15 个任务小样本中，运行时行为规则把触发率降到 0%，而提炼时静态审核后仍有 6.7%。但将两层防御组合后反而出现 13.3% 触发：前置过滤改变了 skill 库，路由器选择了另一批未被原有运行时规则覆盖的 skill。

在 A2S 上，针对 SkillX 编写的规则几乎无效；观察失败后扩充规则，触发率才从 85.0% 降至 20.0%，组合后为 5.0%。由于这些规则是事后调优，这部分只能视为探索性结果。

## 这篇工作的主要贡献

1. 提出了一个区别于传统 memory poisoning 的攻击面：经验经过 Agent 自己的学习流程后，会变成新的持久行为对象。
2. 给出了功能化包装的抗转换攻击思路，并用配对实验说明明显恶意措辞与合理功能叙事在提炼后具有不同的可检测性。
3. 在两个结构不同的 skill 提炼系统上验证了“提炼白化、跨层持久化和后续路由”现象。
4. 指出 skill 生命周期必须保留来源关系；安全系统不能把“转换后的产物”自动视为可信内容。

## 局限与阅读时需要注意的地方

- 全部实验只使用 DeepSeek-v4-flash，尚不能证明结论对不同模型和提炼器普遍成立。
- 主要 ASR 是基于路由和策略违规检测器的代理指标，并未在真实外部服务上执行攻击。
- 数据来自合成的 AppWorld 风格轨迹，不是真实用户长期使用产生的经验。
- 防御实验样本很小，运行时规则是手工正则，干净任务误报率没有完整测量；A2S 的增强规则还是观察失败后才补充的。
- 两套系统的提炼产率、skill 库构成和路由方式不同，因此跨系统数字只能用于说明风险存在，不能直接比较强弱。
- 补充的代码生成验证只有 4 个污染任务和 2 个干净任务，证据量有限。

## 对 Agent 系统设计的启示

最重要的工程启示是把 skill 当成具有数据血缘和权限的供应链产物，而不是普通摘要：

- 为每个派生 skill 保存源轨迹、提炼版本、模型和转换链路；
- 删除或隔离源经验时，递归撤销、重审或重新生成所有后代 skill；
- 在原始经验、提炼后产物、入库前和运行时分别检查，不能沿用一次安全判定；
- 安全判断应以实际动作、工具调用和权限边界为中心，而不是只看名称和文档；
- 对高风险工具使用最小权限、沙箱和显式授权，即使某个 skill 已经通过静态审核；
- 对多层防御做端到端回归测试，因为前置过滤会改变后续检索和路由分布。

## 我的评价

这篇工作的价值主要在“安全边界的重新定位”：真正危险的不只是污染记忆被再次检索，而是系统会把不可信经验编译成一个看似可信的新对象。80% 的删除后存活率很好地展示了生命周期断裂问题。

不过，目前证据更适合支持“这是一个值得重视的新攻击面”，还不足以证明真实部署中的普遍攻击成功率。尤其是单模型、代理指标、合成轨迹和小规模防御实验限制了外推。后续最关键的验证应是多模型、多种自进化框架、真实长期经验池、实际工具执行，以及带完整误报/漏报统计的 provenance-aware revocation 机制。
